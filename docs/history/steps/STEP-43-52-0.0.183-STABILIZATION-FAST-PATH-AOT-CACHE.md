# 0.0.183 — physically closed-path runner + Step-50 calibration + Codemagic AOT cache completion

Scope is deliberately frozen at Step 52. Step 53 and later runtime boundaries remain unopened.

## Device ergonomics

A new fresh-process-only, one-shot launcher button executes the already physically closed same-process chain using the existing step implementations and reports:

`Step 15 A–C → Step 35.0.32 MODEL-BOOTSTRAP → Step 36.0.5 → Step 37.0.1 → SKIP Step 38 → Step 39 → Step 40.1 → Step 41 → Step 42 → Steps 43…52`.

The runner does not bypass a gate. After each existing method returns it requires that step's exact gate summary and Core closure flag before advancing. Any non-closed return stops the runner; later steps are not invoked and a process relaunch is required. Step 15 Gate D is intentionally not run because the proven same-process Step-35 path requires only Step 15 A–C. The convenience runner writes `PhysicallyClosedPath-ToStep52.txt` in addition to all existing per-step reports. Rendering must be frozen after Step 52.

## Step 50 timing calibration

The first supplied 0.0.182 Step-50 attempt successfully started and stopped rendering but the first managed continuation arrived at approximately 2526 ms, exceeding the old 2000 ms evidence ceiling. A fresh rerun was subsequently reported 4/4 through Step 52. 0.0.183 retains the exact 100 ms requested stop delay and stop-before-telemetry/refreeze semantics, but uses a Step-50-specific 4000 ms post-stop evidence ceiling. Step 40's historical 2000 ms ceiling and Step 52's 1500/6000 ms contract are unchanged.

## Codemagic build-time localization

The supplied 0.0.182 Codemagic artifact recorded 3250 s total, of which 3195 s was iOS publish/package. Existing caches restored 2.9 GB of iOS obj/AOT intermediates and 1092 AOT outputs. The MSBuild binlog nevertheless reported the missing `bin/Release/net9.0-ios/ios-arm64/AOTCompileInputs.cache.uptodate` output and still ran roughly 182 LLVM `opt` and 182 `llc` operations.

0.0.183 keeps workflow ID `ios-canonical` and the existing caches, then adds only:

- `AOTCompileInputs.cache`
- `AOTCompileInputs.cache.uptodate`

from the canonical Release/net9.0-ios/ios-arm64 `bin` directory. It does not cache the entire `bin` tree. `scripts/codemagic.sh` reports each marker's pre/post presence, byte size, SHA-256 and mtime, plus counts of AOT-up-to-date messages and LLVM opt/llc executions extracted from the binary log. The first successful 0.0.183 build seeds these newly declared cache paths; the following warm build is the first decisive speed measurement.
